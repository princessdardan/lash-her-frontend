# Reviewed Phase 2 contracts

This bundle pins the exact Course and Community source artifacts consumed by the Phase 2 frontend. The released manifest and compatibility-review.json publish the reviewed source contract; they do not certify staging, authorize deployment, or enable features. The historical ../v1 bundle remains unchanged.

The source pins reference Course `120f42ecd722685dcb232332855bf3a43d01a1ca` and Community `8225015708a3a14a15dc8de2bf68b3a7510df59a`. Both account-command operations retain the canonical v1 request and add the guarded staging sequence-gap envelope. The exact enrollment event and lifecycle boundary bytes carry forward.

The compatibility review is against the released v1 bundle archived at frontend commit a08e4659ab37cd989f7d87dab0116f87eac965ec. It inventories every normalized operation/component delta and binds the exact before/after hashes. The 23 changed Course operations require coordinated API and frontend deployment: catalog and curriculum responses add versioned Portable Text, metadata, access modes, captions/transcripts, pagination and archival; authoring inputs require aggregate revisions and bounded validated content; progress separates resume from maximum watched position and requires a compare-and-set revision. Protected operations document account-state denial. Media adds lifecycle control and signed thumbnails without extending the 600-second playback lifetime. Existing grant and enrollment queries add the explicit free-enrollment source/reason and bounded identifiers. These are intentional P2-02/P2-05–P2-11 changes and must not be treated as a rolling compatibility guarantee for old clients.

All administrator operations advertise adminBearerAuth, matching the separate canonical administrator audience and capability enforcement. Learner bearer credentials cannot authenticate administrator operations.

Identity profiles, lifecycle commands/receipts and enrollment-event bytes retain the published v1 semantics. The boundary document changes only its informational title. Community includes dedicated account commands and exports, course discussions, moderation, member profiles, notifications and media. The private export response adds optional Community records for P5-07. Existing private enrollment and authority paths remain unavailable through the public gateway. This update adds the internal read-only Course checkout offer for P4-05. The frontend owns checkout, tax and payments.

Paid courses may be published only after normal validation. Archival denies protected learning access for existing purchases, preserves historical references and grants, and derives Community access from remaining eligible grants. Existing playback can continue until its issued token expires, at most 600 seconds. Archival creates no automatic refund or payment cancellation. Restoration requires validated republishing and cannot override revocation, expiry or account restrictions. This follows the owner-approved paid-publication/archive policy in docs/api-integration/decisions/2026-11-05-paid-publication-archive-policy.md.

Generate frontend types and runtime validators with npm run contracts:p2:generate and verify with npm run contracts:p2:check. Adapters reject undeclared fields, malformed/missing fields and undocumented statuses without coercion, defaults or stripping; declared maps retain map behavior. Contract integrity, exact Git/source pins and the committed compatibility review must all pass before candidate artifact publication. Source changes require a newly reviewed manifest and regenerated adapters. Staging certification and the single-operator release procedure remain separate requirements.

The Phase 3 candidate adds the authenticated legacy practice-progress operation. It requires a mapped free course and active enrollment, imports only into missing progress rows, and leaves graded completion to Course assessment. The staging rehearsal and feature admission remain separately controlled.
