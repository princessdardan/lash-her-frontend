# P2 historical provider live gates

Configured historical C07/provider scopes are **not currently release-qualified**. The shared implementation has an executable positive path for source-proven inapplicability with actual contradiction reads. It also observes many concrete effects, but several configured-path requirement reducers are missing. Obtaining credentials or recording a Console observation does not implement those reducers. Application SQL still requires actual historical zero active **and** uncertain effects under both locks.

This register describes read-only preparation and possible bounded source extensions. It authorizes no deployment, provider control, credential rotation, admission change or SQL application. The accepted C07 and private host/network/credential handoff remain accepted; stale preparation fields are not a request to supply them again. Source baseline: `b7419df3`; C07 `b99d4f346696f897fa6a6729dfcc52d6503fe8d6`. [Recorded exact requirements](baselines/2026-11-05-p2-historical-provider-live-gates/source-requirements.json) contain all 36 families, source/table annotations and four global SQL obligations. ## Per-surface prerequisites

Prepare one record for each deployment/direct caller, including affected previews in either repository-linked project. Keep these identities together: `surfaceSha256`, `sourceCommit`, `sourceInventorySha256`, `requirementsSha256`, `configurationRecordSha256`, and `provenanceSha256`. Same-source peers cannot share a closure merely because their Git hash matches.

1. Resolve the accepted immutable original configuration reference and complete original key catalog privately. A current project environment, project name, `target:null`, false flag, masked value or missing private preparation field proves no exclusion. Bind original staging/sandbox selectors and exact provider account/application/location/client/calendar/hook identities. Runtime credential equality is checked privately; never hash credential values into evidence.
2. Observe every catalog-present source SQL path: `BACKUP_RESTORE_DATABASE_URL`, `DATABASE_URL`, `STAGING_DATABASE_URL`, and `TEST_DATABASE_URL`. Use the source-owned TLS/role/OID/readonly/parent-marker collector. Alternate databases remain metadata-only; another SQL target alone cannot exclude provider effects. Selected staging roles require actual NOLOGIN and zero affected sessions. Production-target deployments and production native schedules remain outside mutation scope.
3. Retain immutable normalized original SQL snapshots, declared intent/idempotency references, provider IDs and accepted/lost-ack observations before controls. Establish actual ingress/direct-caller fencing and the closed compatible bootstrap. After any declared recovery, append separate current observations and prove the allowed transition; never replace the original snapshot or replay a lost acknowledgement.
4. For each exact family, cover its `original-configuration`, `durable-intents`, `accepted-request-completeness`, and any `callback-persistence` IDs actually present in the verified source. A no-capability closure also includes all four global SQL requirement IDs. A future configured-capability reducer must establish the original binding without pretending that a present credential was absent, then independently reconcile accepted requests and continuations.
5. Retain actual page/cursor coverage, observed identity and time interval, unfiltered statuses, object/attempt IDs, exact outcomes, immutable joins and source-owned sanitized receipt hashes. Document which provider records are unavailable or truncated. An assertion, screenshot of an empty filtered table, elapsed wait, successful refresh, token denial, or an aggregate usage counter cannot supply missing coverage.

All three residual channels remain mandatory: `unresolvedFrontendSqlFamilyIds`, `unresolvedExternalCapabilityFamilyIds`, and their sorted union `unresolvedFamilyIds`. Only the private-SQL scope gates this barrier. Public Sanity authoring/Mux Studio capability stays an explicit external residual; no unrelated credential, signer, asset or media retirement is required.

## Supported evidence procedures and extension boundaries

### HighLevel

Use the exact subaccount/company/app and source lifetime. Read complete workflow definitions and each workflow's step logs with unchanged cursors and explicit adjacent UTC windows; retain unknown statuses. The [v3 workflow logs contract](https://marketplace.gohighlevel.com/docs/ghl/workflows/get-workflow-logs/index.html) limits queries to 30-day spans within 60 retained days and is available only for selected subaccounts. Permission failure is unknown, never an empty result. A logged execution ID identifies a provider run; same contact/workflow/time is not the application's immutable journey key.

For a real candidate run, open the exact workflow's Execution Logs/Enrollment History, then use the [message-details Workflow deep link](https://help.gohighlevel.com/support/solutions/articles/155000003992-workflows-improved-execution-logs-enrollment-history) to retain the actual execution/message association and downstream outcome. Capture source time, pages/filters and the positive exit/delivery record; this documentation does not establish a bulk-export API. Inspect exact app webhook identities and all relevant attempts in the [Webhook Logs Dashboard](https://marketplace.gohighlevel.com/docs/webhook/WebhookLogsDashboard/), whose retained window is 30 days.

**Next adapter:** consume only concrete execution/message/webhook receipts that can join original immutable intents and provider IDs, preserving retry/wait/downstream states. Whole-scope coverage also needs original retained evidence for every applicable period outside those windows. Neither UI nor API can reconstruct expired absent history. Without an authentic join or coverage, retain uncertainty; OAuth uninstall and access denial do not cancel previously accepted workflows or prove delivery.

### Resend

Keep the existing complete account-email, contact/membership/topic and broadcast observations. Add read-only [API log listing](https://resend.com/docs/api-reference/logs/list-logs) and [exact log retrieval](https://resend.com/docs/api-reference/logs/retrieve-log): logs can expose an accepted request/response whose application acknowledgement was lost. Match the private request to the original immutable source intent and retain only safe hashes/IDs/outcomes. No token, address, body or private log payload belongs in public evidence. [Documented CSV exports](https://resend.com/changelog/exports-general-availability) cover emails, broadcasts, contacts, domains, logs and keys; retain original filters/account/interval and bytes privately. They do not document an event-occurrence export.

Enumerate [all automations](https://resend.com/docs/api-reference/automations/list-automations), [all runs per automation](https://resend.com/docs/api-reference/automations/list-automation-runs) without terminal-only filters, and [each run's steps](https://resend.com/docs/api-reference/automations/get-automation-run). Bind trigger/step output to actual source events and exact downstream email IDs; a completed run alone does not prove email delivery. [Event listing](https://resend.com/docs/api-reference/events/list-events) returns definitions/schema, not a ledger of `events.send` occurrences. Actual run retention, removed automations and attribution still require evidence; pagination is not an all-time audit guarantee.

**Next adapter:** fixed GET classifiers and bounded log/run normalizers, source/intent/event/run/email joins, a callback persistence reducer, and explicit missing coverage. The official [OpenAPI](https://github.com/resend/resend-openapi/blob/main/resend.yaml) defines cursor pagination for logs/runs and statuses; do not invent routes. A separately reviewed control may use the documented [stop-automation operation](https://resend.com/docs/api-reference/automations/stop-automation), but its acknowledgement would still need independent run/downstream readback and is not authorized here. Resend documents [30-day email/log retention on listed standard plans](https://resend.com/security/gdpr/); discover actual available coverage rather than requiring a new plan or assuming expired evidence exists. An archive gap remains unknown. Original `APP_ENV=staging` can exclude only the exact audited broadcast guards, not contacts/events or unrelated manual template operations.

Charge, refund, cancel and link-retirement actions require the concrete reviewed release, not this discovery task.

### Sanity private SQL callbacks

No live response has verified this assumption. Hook disable alone does not drain queued or accepted work; an unsigned 401 probe does not fence signed callers.

**Next adapter, narrowly feasible:** bind those actual outstanding-delivery receipts to the exact source callback path, actual old SQL denial/session retirement and closed replacement admission. Verify the historical handler performs synchronous private stock SQL with no uncovered provider continuation; preserve existing stock rows as original state rather than demanding their deletion. All original signed/direct callers and already accepted callbacks still need coverage. Only then may a source reducer cover the callback family without claiming the original secret absent. Missing caller or delivery coverage remains unknown. Do not broaden this work into public Sanity/Mux author or media retirement.

## Selecting the next extension

First obtain the actual per-surface applicability/coverage register through the accepted private runtime; no new secret collection is implied. Implement only a lane that the selected scope needs. Sanity's authoritative outstanding-delivery surface plus synchronous SQL path is the smallest candidate. Resend log/run observation is the next concrete read-only discovery lane. HighLevel/Square retained request/execution evidence can resolve particular effects, but an unavailable historical interval or immutable join may remain irrecoverable. Chit transient history needs real original receipts or a documented provider archive, not a guessed API.

A source extension is eligible for shared consumption only after it validates exact context/requirement IDs, derives observed outcomes without caller completion flags, preserves original receipts, refuses partial/contradictory/expired coverage, and passes actual fixed-transport plus real SQL positive/negative qualification. This register supplies no such new reducer and closes no live gate.
