# Single-operator release simplification

Dardan requested: “simplify the staging release policy. Additionally, I would like the production policy to be as simple as possible for a single developer to mantain”. Accepted November 1, 2026. This supersedes the earlier same-day external signed-source-gate choice and the October 29 Course separate signed-executor requirement. No second operator, paid plan, repository visibility change, independent signing authority or hosted release service is required.

The canonical [release policy](../release-policy.md) defines one manual release action, normal CI, immutable artifacts, explicit environment/target selection, private scoped credentials, serialized forward migrations and one durable receipt. Production additionally requires the exact staging-tested artifacts, a current recovery point and explicit production confirmation. Staging/production remain separate. Protect branches where available without a subscription prerequisite.

Removed: external source/migration approval keys, enrollment/custody evidence, identity discovery, per-run permits and short expiry windows, first-attempt-only source builds, mandatory environment reviewer clicks, mandatory GitHub App registration, separate external executor/federation and custom approval ledgers. Keep native artifact provenance and workload OIDC, TLS, target/lineage locks, test/seed guards and safe migration/recovery behavior. Existing secret stores may be reused; AWS values resolve privately with asm-exec.

Local changes replace the source-signing workflow path with authenticated sole-operator dispatch and exact source/current CI checks. Source tokens use one read-only repository secret. The release manifest records approval without claiming a signature; production completeness checks bind staging-tested sources/images. The old Course signed prototype is retired and disabled. A straightforward operator migration/deployment adapter remains engineering work under this policy; its absence is not a reason to request obsolete signing/executor setup.

No remote settings, credential values, keys, publication, migration, infrastructure or delivery activation were changed. Billing requirements remain removed and monitoring remains deferred. P1 task completion still requires its live technical evidence. Earlier reports remain dated historical evidence. The prior setup hold is superseded only for this explicitly requested local policy/enforcement revision; no live operation is implied.

Later November 1 implementation: the [operator migration command](../operator-migrations.md) and [local evidence](../baselines/2026-11-01-operator-migrations.json) now cover both API entrypoints/images, private schema exports, bundle preparation and host serialization/credential isolation. Full runtime deployment coordination and actual provider staging verification remain open. This progress does not activate production.
