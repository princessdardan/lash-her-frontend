# Learner experience candidate

`INTEGRATION_LEARNING_ROUTES_ENABLED=true` and `INTEGRATION_COURSE_READS_ENABLED=true` select the Course-backed `/courses`, canonical `/courses/[slug]`, `/academy`, course outlines, and `/academy/courses/[courseId]/lessons/[lessonId]`. The new presentation switch defaults off and is separate from the six independent capability controls. When off, the existing Sanity/browser-cookie course detail route and its local progress behavior remain available. This does not perform the Phase 3 content/progress migration, retire public media, or enable production.

Customer learning additionally requires the independently enabled customer-access and customer-auth controls, a current database session, and the Course API's effective-access decision. Public catalog responses contain metadata and explicitly public preview references only. Authenticated preview links pass a public course slug for canonical validation; the server verifies course/lesson membership and the receiver still decides preview eligibility. Preview UI does not claim saved enrollment, progress, or assessments.

The learner sees catalog pagination, free enrollment, account-bound course progress, course/lesson navigation, versioned Portable Text, transcripts, captions, a signed Mux player, and practice/graded assessment attempts. Paid enrollment remains unavailable. Browser traffic uses named same-origin academy handlers; API JWTs, service credentials, and workload proofs are never exposed to the browser. Mux playback/thumbnail tokens remain private/no-store and renew through a fresh effective-access check. Failed renewal pauses and removes the player. Mux analytics/cookies and browser volume/mute preferences are disabled.

Progress writes serialize in one player using `expectedProgressRevision`. Resume may move backwards; max watched remains monotonic. A stale revision reloads the receiver's state and blocks local replay until the user reloads. Offline failures retain the latest local queued update in memory for explicit retry; they do not claim confirmed saving. Pause, navigation, and visibility/page-exit flushes use bounded JSON with CSRF headers, including keepalive where needed. No new learning progress is written to local storage. The receiver grades every attempt, owns completion, and retains revisioned history; generic completion is available only when the assessment lookup confirms no quiz. Assessment outages cannot silently qualify a graded lesson.

Progress recovery also retries a failed authoritative completion read when no write is pending. Exit updates retain keepalive while waiting behind an active write, and updates queued while an empty or completed drain settles remain part of the flush. Loading a revised assessment first settles the current playback position and refuses to discard an unknown write outcome. Explicit retry recovers a lost acknowledgement through the receiver's revision check; an authoritative refresh then resets the assessment and completion state from the server's current version. Playback authorization has an independent hard expiry, so a stalled renewal cannot retain an expired player or install a late expired response.

New writers are the named free-enrollment, progress, and assessment-attempt methods, called only through whole-operation writer admission. Their route exports and direct helper callers must remain in the release source/producer inventory. Public catalog, authenticated content/progress/quiz reads, and session-fenced token issuance do not mutate frontend SQL. Receiver quotas remain operational accounting owned by the respective receiver. The migration presentation flag does not bypass capability gates or admission.

Local verification uses `tests/learning.playwright.config.ts` with a dedicated migrated loopback database (`LEARNING_E2E_DATABASE_URL`). It exercises actual frontend database sessions and same-origin adapters against synthetic workload-authenticated Course responses and intercepted Mux media, on desktop/mobile. It proves local UI behavior, not deployed provider certification. Actual Google, Resend, Mux, account-to-learning staging certification, accessibility review, and release-source admission qualification remain P2-12/G2 conditions.
