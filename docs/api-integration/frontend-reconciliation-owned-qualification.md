# Owned reconciliation route qualification

P2-00 continuation after PR #86. This component exercises the exported authenticated reconciliation GET through a loopback HTTP bridge, the real admission runtime over verified PostgreSQL TLS, and the migrated business database. It does not deploy Next.js or enable live admission, pending SQL, schedules or customer capabilities.

The existing migration fixture owns the new loopback TLS/SCRAM cluster, application migrations, ledger bootstrap and distinct operator/runtime roles. A child process receives only fixture configuration and uses the same database/login for application writes and admission. All application dependencies and all four recovery runners are production implementations. Square and Resend HTTP responses are intercepted; unexpected outbound fetches refuse. No live provider endpoint or configured database is accepted.

Required checks are authentication and closed-admission refusal before effects; four empty successful independent entries with new work closed; nonempty service terminal remediation, customer email claims/receipts, split cancellation and commerce capture receipts; policy closure during each batch; failed concurrent queries with an actually blocked database sibling; missing request intent; actual ledger-backend loss; caught email/split provider failures; and admission-off compatibility. Active and uncertain records must prevent drain/restoration until the request has finished and the fixture operator explicitly reconciles the actual outcomes. Existing business/provider keys must survive, and no fault may replay effects.

The fixture must stop its cluster and close HTTP/database resources even after failure. Its retained output contains check names, source/evidence hashes and counts only. Real Square/Resend delivery, a deployed immutable Next.js runtime, exhaustive producers/historical fencing, provider drain, live bootstrap and the parent release/restoration coordinator remain separate requirements. P2-00 stays in progress.
