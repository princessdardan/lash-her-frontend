# Owned bootstrap fixture: failures and correction

CI run `42139490765`, job `127635940949`, checked out exact frontend `ab34cf9bedde69cf2ddce54b717c9dc1a181c5d6` on Ubuntu 24.04. It built the immutable migration image, passed its offline boundaries and built the owned PostgreSQL 18 fixture. The operator child then failed in `frontend-bootstrap-owned-probe/configuration`; its original underlying exception was not logged. The missing qualification-upload files were secondary.

The actual protected route imports `gateway-transport.ts`, which eagerly imports `ops/gateway/routes.json`. That file was absent from the mounted source context. An independent copy of the actual CI mount inputs reproduced the real route's `MODULE_NOT_FOUND`. Adding only the unchanged gateway policy made the same actual module graph import pass, without a database or network call. This identifies a concrete required closure defect without claiming access to the hidden original exception.

The first proposed correction, `71f6020b` (root `646bb7f6`), added a fixture Dockerfile COPY. I assumed the repository root was the build context. Root caught that both workflows build with `ops/platform` as context. Actual CI run `42140767192`, job `127640247273`, then confirmed the COPY checksum failure: `/ops/gateway/routes.json` was not found in that context. Its logs and failed steps are retained. The initial local import guards modeled the file without checking the actual build context; their success was not a Docker build result.

The final correction `7072148ed2793ad1c542b550a800818e37dd1309` removes that COPY. Root's `f07430bbfb7985bafe024eb43daa7f78c6116da3` adds the exact unchanged policy as a read-only file mount in both source CI and candidate rehearsal. The actual route graph guard now follows aliases and re-exports, requires the real mounts, and reproduces failure when only the policy is removed. Separate guards derive each workflow's real Docker build context and reject the former invalid COPY. All nine focused tests and lint passed.

The full owned PostgreSQL 16 parent passed against the same runtime inputs: 83 migrations, the actual bootstrap HTTP export/SDK, verified TLS, current admission policy and catalog hash, authentication/feature/closed-admission refusal, prior writer/worker/reconciliation gates, 17 identity database tests, 19 lifecycle database tests and 43 actual identity/admin/lifecycle route checks. This local source fixture has `packagedCliVerified: false` and a synthetic migration fixture source/digest; it does not qualify a published image. The subsequent correction changes only test packaging and guards, so the identical runtime database run was not repeated.

The bootstrap child now emits fixed phase and failure classes, with a fixed dependency name when recognized. It does not expose raw exception messages, stacks, URLs, environment values or credentials.
