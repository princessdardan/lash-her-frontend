### Repeating isolated database checks

During this run PostgreSQL 16 used port `55464` and PostgreSQL 17 used `55465`; database names were `lash_course_p04_test`, `lash_community_p04_test`, and `lash_frontend_p04_test`. The temporary clusters were stopped after testing. No repository `.env` was changed.

For each API, inject `DATABASE_TARGET=test`, `NODE_ENV=test`, `TEST_DATABASE_URL` pointing to its disposable loopback database, and `RUN_DATABASE_INTEGRATION_TESTS=true`; run `npm run db:migrate` then `npm run test:database`. Round trips use `DATABASE_ADMIN_URL` pointing to that disposable cluster's `postgres` database and `MIGRATION_ROUNDTRIP_ALLOW_DESTRUCTIVE=true`; the scripts create/drop their own scratch databases.

For frontend, inject the same local URL into `DATABASE_URL` and `TEST_DATABASE_URL`, append `?sslmode=disable`, and set `PRIVATE_DB_MIGRATION_TARGET=local` plus `PRIVATE_DB_MIGRATION_HOST=127.0.0.1`; run `npm run db:migrate` then `npm run test:unit:db`.
