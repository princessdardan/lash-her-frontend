# Administrator authorization actor isolation

The [before observations](before-observations.json) reproduce a header-keyed actor-cache boundary failure on source `3ba66f46`. Concurrent independent authorization operations with the same caller-selected `x-lash-admin-request-id` return the first owner's actor to a different active account or a disabled account, without the second account's repository reads. A second request after disabling the first account also receives its prior active actor; a different-header control correctly denies the disabled account. Independent authorization operations within one request share the same stale actor until response cleanup. The [failed regression](before.tap) retains the actual and expected observations.

The installed Next matcher utility confirms that the current proxy matches `/admin` pages and excludes `/api/admin` routes. The proxy therefore does not replace the incoming header on the administrator API paths used by this reproduction. These results establish source-level isolation failures under a shared process and colliding caller-selected headers. They do not demonstrate deployed exploitation or arbitrary access to an unrelated production account.

Commit `e5af4b12` removes the global header-keyed map and its `after()` cleanup. An admitted authorization operation now owns one actor promise in `AsyncLocalStorage`; nested actor/permission reads reuse that promise, including without a request header, and independent operations resolve their own identity and account state. Known denials retain clean settlement, and a cached rejected promise cannot conceal an uncertain persistence or audit outcome. The [after observations](after-observations.json) verify the corrected boundaries.

The collision fixture uses the real exported authorization functions, real Auth.js decoding of locally signed synthetic Google JWT claims, real Next request storage and `AfterContext`, and actual account/permission policies. Its user repository and admission protocol peer are controlled. It does not connect to a configured database or an external provider. The separate [owned PostgreSQL 16 receipt](owned-postgres16.json) passes all 43 existing actual auth/account/admin/cron entry cases, 14 admission checks and 33 database regressions, including real administrator SQL commit-acknowledgment uncertainty. Its disposable TLS/SCRAM cluster was stopped and removed.

All [18 focused tests](focused-after.tap), changed-file ESLint and [full TypeScript checking](typescript.txt) pass. The bounded provider-policy test update requires the exact reviewed `@lash-her/auth-core` fork identity while retaining the `@auth/core@0.41.3` upstream security baseline; no dependency files changed. [Validation](validation.json), the [candidate inventory](candidate-source-inventory.json) and [source bindings](source-bindings.json) identify the exact source, fixture scenario and artifacts. Earlier identity qualification and frozen failure records remain unchanged. No live database, provider, schedule or production configuration changed; native Next/browser and deployed provider certification remain outside this record.
