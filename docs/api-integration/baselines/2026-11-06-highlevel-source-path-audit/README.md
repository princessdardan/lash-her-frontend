# HighLevel historical source-path audit

The frozen conservative subset contains **35 deployment surfaces at 25 exact revisions**. Source inspection separates 12 surfaces without a HighLevel integration, 21 using the C07 location-OAuth credential boundary, and two using an agency-token exchange variant. These are candidates for a bounded source-policy extension, not runtime exclusions or release evidence. The current profiles still mark all eight HighLevel families reachable and do not reuse their credential predicates.

This audit changes no profile, selector, provider reducer, runtime configuration or admission state. It reads Git objects and existing public evidence only. It does not establish original configuration, provider account identity, SQL applicability, old accepted-effect completeness or credential retirement. The frozen 81-surface register remains unchanged; neither its 17 unprofiled nor its five missing-source surfaces are excluded. Later exact aliases are outside these counts.

## Configured effects remain unresolved

The source permits direct contact updates/deletion and workflow removal while new sync/marketing work is paused. Privacy deletion can erase provider IDs and effect payloads; retention can delete old receipt/job rows. Workflow enrollment acknowledgment is distinct from downstream workflow execution, conversations and messages. Complete current SQL or provider lists do not retrospectively establish those missing outcomes.

The four store/sync versions and two retention versions share the audited credential boundary but differ in conversion, source-removal, consent, historical-job and follow-up behavior. `6e0e3d41` also adds course-signup notes and source-scoped backfill. A configured history reducer must join the exact originating source intent and provider outcome; these changes cannot be erased by a common library/SDK fingerprint. Existing admin `confirmed`/`absent` form choices and textual evidence references are not a machine-verifiable accepted-request completeness reducer.

The next bounded implementation should therefore be **source-policy qualification first**: exact-revision absence facts for the 12 integration-absent surfaces, then pinned provider-only credential gates for the 21 location-OAuth surfaces, and a separate agency/caller audit for the remaining two. Only positively configured, source-applicable scopes that survive that process should select further provider-history work. Every resulting runtime decision still requires the existing source-owned original configuration/SQL/effect contradiction checks. No step here authorizes public Mux/Sanity retirement, provider mutation or production controls.

## Reproduction and limits

The audit pins frontend source `caea30f6297a0da0b441c20cc9598ab1e798e192` and the earlier frozen register by hash. `verifiedSourceRequirements(repository, exactRevision)` was invoked for each of the 25 revisions; selected blobs were then read using `git --no-replace-objects cat-file --batch`. Core/credential variants were compared by actual blob identity; differences in OAuth/config/store/sync/retention/manual callers were inspected. The recorded import scan is supporting navigation, not a completeness assertion. Absence review also inspected the inventory's direct network sites: other-provider clients, same-site browser requests, allowlisted Chit Chats label reads, Strapi migration reads and the fixed purchasability GET. The Strapi/manual readers do not become general approved direct callers.

No API, provider, catalog, private-value or SQL read was performed. The JSON is evidence of source facts only and is deliberately not accepted by runtime closure APIs.
