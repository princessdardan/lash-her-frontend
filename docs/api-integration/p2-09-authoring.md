# P2-09 authoring candidate

The `/admin/courses` workspace uses the existing protected admin shell and `courses:edit` permission. Its navigation remains hidden until the server-only Course rollout flag is enabled. Customer lifecycle navigation is a separate owner-only flag. No production capability is activated by this source package.

The workspace supports catalog pagination, draft creation, CAD/access/tax metadata, covers and SEO, module/lesson creation and editing, atomic full-sibling ordering, archival/restoration, structured version-1 lesson content, transcripts, revisioned quiz authoring, media upload/replacement/status and captions, publication diagnostics, and explicit publication under the reviewed Course revision. Published courses must return to draft before authoring. Media status/reconciliation remains available without authoring permission changes.

All browser Course traffic goes through the named explicit `/api/admin/courses`, `/api/admin/modules` and `/api/admin/lessons` handlers owned by the shared service-boundary package. That package authenticates editor capability, checks same-origin JSON/CSRF, validates the pinned request and response contracts, enters writer admission for mutation effects, sanitizes errors and invalidates public catalog paths/tags. Its bounded public catalog TTL provides recovery if invalidation is missed. Authoring pages, responses, progress and media decisions remain private.

Each save carries the course aggregate revision captured by the open editor. Conflicts preserve the unsaved form; the UI requires an explicit reload. Choosing another editor or a curriculum/lifecycle mutation asks before discarding dirty changes, and browser unload protection covers an open dirty form. Concurrent losers are never automatically replayed. Publication readiness is informational: publishing repeats validation under the Course root lock and expected revision.

Video bytes go directly to the one-off upload URL returned by the validated handler, with credentials omitted and redirects refused. The UI never receives Course signing keys or workload credentials. Failed or uncertain provider operations require status/reconciliation before another intent; the UI does not automatically repeat upload or caption mutations. Course media services own durable intent receipts and recovery, covered by their separate database qualification.

Local evidence is tracked separately from deployed certification. Source type/lint checks and focused form/navigation/request-security tests do not establish real provider/browser staging certification. The final matching Course artifact, owned browser scenarios, repository build/checks and deployed authoring/learning certification remain required before closing P2-09 or G2.
