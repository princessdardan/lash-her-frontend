# Square Team Attribution and Employee Calendar Remediation

## Purpose

This ledger tracks the code remediation for the staging audit of the Square
team-attribution and employee Google Calendar self-service extension. It is the
implementation source of truth until every code-resolvable finding is closed
and the remaining environment validations are handed to the owner.

Status values:

- `planned`: implementation has not started.
- `in_progress`: code or regression coverage is being changed.
- `verified`: focused automated coverage passes.
- `environment_validation`: code is complete, but live Square or Google
  confirmation still requires an owner-controlled dashboard/account.

## Environment validation after code completion

These checks require owner-controlled external systems and are not substitutes
for the automated evidence above:

- Refresh the Square Sandbox team directory and confirm active, inactive, and
  missing mappings display correctly.
- Confirm the Square webhook subscription includes `refund.created` and
  `refund.updated`, then verify completed refund events are received.
- Complete a direct Sandbox booking and verify Square records the expected
  `team_member_id`.
- Complete employee OAuth with a real Google account, reconnect it, discover
  calendars, and verify a promoted booking destination receives an event.
- Confirm Google token revocation and duplicate-account messaging with the
  production OAuth client configuration.
- Run the optional live browser smoke only against a separately isolated
  test target using the target-bound confirmation documented in
  `tests/support/README.md`.
