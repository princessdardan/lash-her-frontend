# P2 identity probe fixture preparation

`prepare-p2-identity-probe-fixtures.mjs` is a fixed CI preparation command for the existing identity negative-probe tests. It accepts no arguments, URLs, revisions, commands, database configuration or provider configuration. Its only private input is the existing read-only `PLATFORM_SOURCE_READ_TOKEN` environment value used for the two private sibling repositories.

The command reads the released `contracts/api-integration/p2-candidate/manifest.json`, requires the canonical Course and Community repositories and artifact paths, and uses their exact nonzero revisions. It creates a new mode-0700 directory under the system temporary directory outside Git, initializes two empty repositories, and fetches only those exact private revisions. The token is encoded in an ephemeral Git HTTPS extra header available only to each fixed `git fetch` child. It is never placed in a remote URL, command argument, Git configuration file, output receipt, npm environment, build environment or test environment. Each checkout must have the canonical credential-free origin, exact detached `HEAD`, a nonzero Git tree, no tracked changes, and no nonignored untracked files. Ignored source and configuration are also refused; only Python bytecode caches and dependencies beneath the two tracked frontend tool lockfiles (`ops/gateway` and `tools/api-contract-toolchain`) are tolerated. The manifest-pinned OpenAPI and enrollment-event bytes are checked before build.

Execution requires Node 24 and npm 11. Each API must retain package-lock version 3 and the fixed `build:production` script `tsc -p tsconfig.build.json`. Installation is `npm ci --ignore-scripts --include=dev --no-audit --no-fund`; build is `npm run build:production`. Commands receive a replacement minimal environment containing no ambient database, AWS, provider, release, signing or application credentials. The disposable directory, npm cache, dependencies and build outputs are removed on success or failure.

After both clean builds, the command invokes the existing test directly:

```sh
node ops/platform/prepare-p2-identity-probe-fixtures.mjs
```

The child receives only the two disposable runtime directory paths. Its TAP receipt must report exactly 19 tests, 19 passes, and zero failures, cancellations, skips or todos. The existing fixture independently checks the selected API Git heads against the same manifest, compares the required compiled modules with source compilation under each API's actual TypeScript settings, and exercises the actual verifier and owned HTTPS route cases.

The one extended mode is explicit and fixed:

```sh
node ops/platform/prepare-p2-identity-probe-fixtures.mjs --recovery-postgres18
```

It first completes the same exact clone, build, and 19-test identity gate. It then verifies that neither API's local Git configuration persisted the read token or any authentication helper/header, changes only the two disposable API checkout roots from mode 0700 to 0755 for the container's non-root PostgreSQL user, and keeps their private parent at mode 0700. The already-built local `lash-her-frontend-migration:postgres18-test` image runs with no network, a read-only root, all capabilities dropped, no new privileges, a 1 GiB memory limit, bounded processes/shared memory, and a 512 MiB temporary filesystem. It receives fixed nonsecret PostgreSQL 18 and source-root variables only. Fixed read-only mounts expose the required frontend source/dependencies and the two disposable API source/dependency trees; the workspace parent, source token, Docker host/configuration, ambient credentials, Node hooks, and host-private files are not mounted or forwarded.

The fixed Python entry `ops/platform/test-p2-recovery-owned.py` must return one JSON receipt proving PostgreSQL 18, 83 frontend migrations, 22 Course migrations, 11 Community migrations, zero skips, no SQL replay, and no recreation of an original frontend terminal receipt. The receipt must also bind all 55 named/derived checks: 17 initial and 17 continuous frontend privilege refusals, 22 API privilege refusals, two legacy API-verifier refusals, the exact 39-fault catalog, the PostgreSQL 18 creator-membership policy, pinned `pg_catalog,public` startup search path with real-catalog/lock observation, and the positive-control/poisoned-parent child-environment isolation proof. This deliberately rejects the original 17-case unsafe proof and every superseded 14/50-check receipt; the failed SQLSTATE 42501 compound superuser setup is not bypass evidence. Missing images, fixture failures, wrong counts, missing named faults, additional output, or unsafe Git configuration refuse with the same fixed redacted failure result. This local container gate does not establish staging qualification.

Success output contains only frontend/API source identities, Git tree and package/artifact hashes, test counts, and negative scope flags. It contains no checkout path, command output, token, key, URL with credentials, database value or provider response. Failure output is fixed and redacted, but identifies one bounded phase and stage: preflight, source fetch, install, build, exact-source proof, identity tests, PostgreSQL 18 recovery, or cleanup; and the applicable frontend/workspace/Course/Community/identity/recovery stage. Raw child stdout, stderr and upstream authentication errors are never returned.

Default mode is exact private-source checkout and owned identity-fixture preparation only. Recovery mode additionally executes SQL solely in three disposable PostgreSQL databases inside its isolated owned container. Neither mode performs a staging request, provider call, image publication, deployment, admission change, service restart, key rotation, release acceptance or Git push. Root workflow wiring and final CI execution are separate. Actual CI and staging qualification remain open.
