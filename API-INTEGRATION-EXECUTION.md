## Task and evidence rules

1. Read the current checkpoint, relevant scope/contract and repository instructions. Inspect actual source/target before acting; historical observations are not fresh preflights.
2. `Depends on` lists implementation prerequisites. Work may proceed across phases once these are DONE. Additional live prerequisites are explicit in task descriptions: deployed learning/commerce/Community certification needs G1 and the applicable migration path; production activation needs G6. An independent local task does not require live release approval.
3. Keep stable IDs; use child/new IDs to split scope. P1-04A is an evidence-backed artifact subset, not a new parent completion. Set active work IN_PROGRESS and implemented work awaiting checks VERIFYING. DONE requires all dependencies and the task's listed completion/certification evidence.
4. Record a concise result, exact source/artifact/environment, evidence class and limitation. Never substitute test counts or a PR for the required behavior. Keep original failures and receipts immutable; link rather than copy them.
5. When an assumption changes, invalidate only affected criteria and return affected certification to VERIFYING. Routine releases recheck their source/CI/smoke and reuse still-applicable initial qualification. Do not requalify everything for an unrelated tooling commit.
6. A finding must identify the existing requirement, affected operation/environment, evidence, priority, owner and closing condition. New scope needs a recorded amendment and task mapping. Later feature requirements do not silently expand G1. Keep explicit operator decisions authoritative for their scope.
7. Before a later feature implementation, complete the applicable [task brief](docs/api-integration/briefs/README.md). Unresolved numeric/product/retention choices must be recorded before the affected behavior is implemented or enabled; no invented business/legal inputs.
8. Update this tracker and the current checkpoint together after material progress. Log new concise results here; retain detailed chronology in [history](docs/api-integration/history/README.md). Synchronize all three scope copies when scope changes.

Statuses: NOT_STARTED, IN_PROGRESS, VERIFYING, BLOCKED (named unmet condition), DONE (scoped criteria passed), DEFERRED (explicitly excluded for now, not completed). Owners identify responsibility; Dardan is the sole operator.
